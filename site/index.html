Filter bars, done once.

Every internal tool grows a filter bar, and every filter bar grows a bad little query language held together with string concatenation. Sluice is that language, written properly: a real parser, a real AST, every value bound as a parameter, and typed autocomplete from the same declaration the compiler uses.

state = "shared" AND team ~ "design" AND NOT active = true

One declaration, three consumers

The schema is the whole configuration. The compiler, the editor and the browser all read the same field list, which is why the autocomplete can never disagree with what will compile.

schema.json

{
  "name": "documents",
  "fields": [
    { "name": "state",
      "type": "enum",
      "column": "doc.state",
      "values": ["shared", "restricted"] },
    { "name": "team",
      "type": "enum",
      "column": "grp.name",
      "dynamic": true }
  ]
}

server

c, _ := sluice.New(schema, postgres.Dialect)
res, err := c.Compile(input)

res.SQL     // a WHERE fragment
res.Args    // every value, bound
res.Fields  // so you can prune joins

// and the reduced schema for the browser,
// with your column SQL removed
c.PublicSchema(dynamic)

browser

const lang = createLanguage(schema)
register(monaco, { language: lang })

// completions, diagnostics, highlighting

What it guarantees

These are the reasons the project exists, and every one of them is asserted by a language-agnostic corpus that both implementations run on every commit.

No text reaches SQL

Values leave the compiler only through the argument list. The only way to emit one is Bind, which returns a placeholder — there is no method that writes a value into SQL text, including for your own custom emitters.

No passthrough

A token the schema does not recognize is a diagnostic with a source position, never something copied into the output. A bare word is not a value: state = shared is a syntax error rather than a clever guess.

No drift

Go and JavaScript are driven through one JSON Lines protocol against one corpus. Adding a language means adding one registry entry; changing behaviour without a case is not allowed.

Install

Zero runtime dependencies on the JavaScript side, and the Go module depends on nothing outside the standard library. 

# the compiler
go get github.com/kilianc/sluice
# the language, and an editor binding
npm install @sluice/core
npm install @sluice/monaco   # or @sluice/codemirror

Four dialects ship today: Postgres, DuckDB, SQLite and MySQL. Sluice compiles a predicate and an ORDER BY — joins, projections and aggregation stay your application's business, and that constraint is what keeps it small enough to depend on.
